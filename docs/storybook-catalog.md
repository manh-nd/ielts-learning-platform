# Storybook Component Catalog & Taxonomy Guide

This catalog serves as the single source of truth for humans and AI agents navigating the IELTS Learning Platform component architecture.

It answers three practical questions for every component:

1. **What kind of component is this?** (Design System Primitive, Design System Component, Pattern, Product Feature, or Product Screen)
2. **Is it part of the current production UI?** (Concrete route or parent consumer)
3. **If not production, why are we keeping it?** (Prototype behavior mining, candidate for cleanup, etc.)

---

## 1. Taxonomy Structure

Storybook sidebar navigation follows a clean 3-tier hierarchy:

```text
Design System/
  Foundations/ (Design tokens, criterion colors, typography measure, severity tiers — Issue #103)
  Primitives/ (Core unopinionated Base UI / shadcn building blocks)
  Components/ (Standardized visual design system components defined in CONTEXT.md)

Patterns/
  Audio/ (Reusable audio waveform and recording controls)
  Assessment/ (Reusable criteria scoring, scorecards, and delta viewers)
  Chat/ (Reusable conversational messaging and streaming transcript primitives)
  Editor/ (Reusable TipTap rich-text editing abstractions)
  Forms/ (Reusable form input compositions like DatePicker)
  Navigation/ (Reusable header bars and user action menus)
  Review/ (Reusable grading banners and diagnostic error annotators)

Product/
  Auth/ (Authentication views, cards, forms, and OAuth buttons)
  Classroom/ (Classroom management workspace, rosters, cards, and dialogs)
  Homework/ (Homework assignment cards, dialogs, forms, learner recording, and teacher review cockpit)
  Speaking/ (Live examiner room, session controls, transcript streams, and speaking prototypes)
  Writing/ (Teacher writing review workspace and timed writing suite prototype)
```

---

## 2. Classification Schema

Every component is assigned one of four canonical lifecycle statuses:

- **`production`**: Actively consumed in shipped production routes (`app/(protected)/...`, `app/(public)/...`, or `app/page.tsx`).
- **`reusable-pattern`**: Composable component with a demonstrated reuse boundary across multiple features or documents.
- **`prototype`**: Working UI pilot surface or experimental workspace not wired to canonical user flows. Retained for behavior extraction or pilot evaluation.
- **`unused/dead`**: Component with zero production consumers and no active story. Documented candidate for removal in Issue #103.

## 4. Maintenance Guidelines for AI Agents and Humans

When authoring new stories or components:

1. **Primitives**: Place new generic Base UI / shadcn components under `Design System/Primitives/<Name>`.
2. **Standardized Design System Components**: Only place components explicitly canonized in `CONTEXT.md` (like `BandScoreBadge`) under `Design System/Components/<Name>`.
3. **Patterns**: Only place components with a verified reuse boundary across multiple features under `Patterns/<Category>/<Name>`.
4. **Product Features**: Place feature-local dialogs, cards, forms, and views under `Product/<Feature>/<Name>`.
5. **Prototypes**: Always preserve existing tags and append `"prototype"` (e.g. `tags: ["autodocs", "prototype"]`), append `(Prototype)` to the Storybook title, and explain retention rationale in this catalog.
